# PM 产品工作流

> 产品经理从「一句话需求」到「可交付原型」的标准化五阶段流水线，每个阶段都有产物文件和强制确认闸门。

## 它解决什么问题

用 AI 做产品设计的常见崩法，基本都出在**跳步骤**上：

- 需求还没对齐，AI 就直接吐一个 HTML 页面 → 交付出来和想象的不一样，全部返工
- 没有统一的设计规范，每做一个页面换一种风格 → 一个系统里十种视觉语言
- 字段口径没人写下来，下次换个会话又要重新解释一遍「这个数按什么口径算」
- 改了一个地方，上游文档没同步 → 文档和实现彻底脱节

这个技能的做法很笨也很有效：**把流程切成五段，每段必须落一个文件，每段必须你点头才往下走。**

## 五个阶段

| 阶段 | 干什么 | 产物 | 闸门 |
|:---:|---|---|---|
| **1** | 需求澄清 | `00-需求笔记.md` | 用户逐条确认 |
| **2** | 写 PRD | `01-PRD.md` | 用户确认 |
| **3** | 定设计规范合同 | `DESIGN.md` | 一次定稿、长期复用 |
| **4** | 设计图 / 线框 | `02-设计图/` | 用户确认布局 |
| **5** | 原型 /（可选）代码 | `03-原型/` | 用户确认 |

## 三条不该被绕过的纪律

1. **禁止跳阶段。** 尤其禁止「需求没澄清就出 HTML」「没有 DESIGN.md 就写页面样式」。
2. **产物必须是文件，不是聊天消息。** 任何 agent 接手时先读已有产物续跑，而不是让你重讲一遍。
3. **阶段 5 必须走 `prototype-html` 技能。** 原型固定产出「左侧界面 + 右侧说明面板 + SVG 连线」的形态，不允许只交一个没有说明的纯界面。

## 目录约定

在具体项目里跑起来后，长这样：

```
<项目目录>/
  00-需求笔记.md      # 阶段 1 产物
  01-PRD.md           # 阶段 2 产物
  DESIGN.md           # 阶段 3 产物（可跨项目复用，放工作区根目录亦可）
  02-设计图/           # 阶段 4 产物（ardot 画布 或 灰阶线框 HTML）
  03-原型/             # 阶段 5 产物（左界面 + 右说明 + SVG 连线）
```

## 本仓库文件

| 文件 | 用途 |
|---|---|
| `SKILL.md` | 技能主定义：五阶段流程、闸门规则、自检清单、迭代回退规则 |
| `DESIGN-模板.md` | 设计规范模板，阶段 3 据此生成 `DESIGN.md` |
| `DESIGN.md` | 一份已定稿的 OA 扁平化设计规范，可直接作为起点 |
| `prototype-html/SKILL.md` | 阶段 5 原型的生成规范（分栏比例、SVG 连线、说明面板分组）|
| `prototype-html/assets/example.html` | 原型结构参照示例（42 KB，照着它理解布局与连线画法）|

## 安装

把这个目录放进你的 agent 技能目录即可：

```bash
# WorkBuddy / Claude Code 等
git clone git@github.com:Carlchenqqq/pm-product-workflow.git \
  ~/.workbuddy/skills/pm-product-workflow
```

不同 agent 的技能目录不同，按你所用工具的实际路径放即可，关键是目录名保持 `pm-product-workflow`、入口是 `SKILL.md`。

## 使用

说出你要做的东西就行，比如：

> 「帮我做一个供应商管理页面」
> 「做个批次报表看板」

技能会自动从阶段 1 开始，**先听你讲需求，再问问题**，不会一上来就画页面。每一步都会停下来等你确认。

## 配套依赖

- **阶段 5 · prototype-html —— 已内置。** 规范与示例都在本仓库 `prototype-html/` 目录里（`SKILL.md` + `assets/example.html`），clone 下来就能用，不需要另外安装。若你本机已单独装过同名技能，用已安装版本也可以，两者内容一致。
- **阶段 4 · ardot（可选）** —— 默认用 ardot 画布画设计图；连不上时会自动降级为灰阶 HTML 线框，流程照常往下走。

除 ardot 这个可选项外，**本仓库是自包含的**。

## 兼容性

不绑定特定 agent。已按 WorkBuddy 的技能格式组织，Claude Code / Cursor / Kiro 等只要能读 `SKILL.md` 作为指令，同样可用。
